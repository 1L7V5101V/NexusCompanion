## 说明与边界

- **流式 delta 在生产为 0 段**：生产 LLM provider 该轮未产生分段 delta（与
  provider 流式配置有关，非 auth 接线范围）。流式帧链路已由本地真实 PG e2e
  （`real-pg-e2e.txt`，stub worker 显式产生 delta）与 C4 dev e2e 覆盖。
- **首次运行失败为脚本缺陷**（非产品缺陷）：`client_message_id` 未用 UUID，
  服务端正确回 error 帧（`ERR_BAD_CLIENT_MESSAGE_ID`），脚本当时未显式处理
  error 帧导致等待空闲回收；已修复脚本（cmid 用 UUID + error 帧即失败）。
  该轮产生的 canary 账号 `8a297ab8-8394-4f77-8004-8dc170e3d7ab` 同样已撤销。
- **部署代码版本**：服务器快照包含 webchat-auth-wiring 主体（`3da7f9d5`）；
  与 main 的差异仅为 `chat_api.py` 黑格式化（无语义差异）及 C15
  （`work-queue`）对 `bootstrap/app.py` 的增量（属 C15 部署范围，与本 change
  验收无关）。核心身份/握手/门禁文件（`web_chat_channel.py`、
  `auth/identity.py`、`auth/ws_guard.py`）与 main 逐字节一致。
- **运维边界**（同 5.5）：本 change 只解决认证闭环；对外部用户开放 MUST 等
  C7 工具隔离 + 存储切换。
