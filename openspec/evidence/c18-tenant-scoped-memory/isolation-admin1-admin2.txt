 这份记录与自动化用例的差别
==============================================================
`tests/memory/test_cross_tenant_isolation.py` 用两个临时租户 id 在两种后端上跑同一套断言，
数据是当场造的。这里跑的是**开发者环境里那两个常驻租户**，读的是真库里的真行，走的是运行时
真正用到的两个函数：`resolve_persona_snapshot`（person 与画像出自同一次借用，ADR-1）与
`ContextBuilder.render_sections`（三条可加载组装路径共用的那个渲染器，ADR-15）。
断言的四件事：
1. canary 进了 A 自己的系统提示——没有这条，第 2 条就是空断言（`## Long-term Memory`
   与 `## 关系状态` 两段的正文在输出里可见）；
2. canary 完全不在 B 的系统提示里（两份提示各 1.6 万字符，只差 72 字符，正是 A 那段内容）；
3. B 的画像四类字段全是 0 字符，即「画像缺失 = 空语义」，没有回退去读共享 workspace 目录；
   B 的关系状态 40 字符是它自己的 onboarding 种子，不是 A 的 44 字符那份；
4. 画像内容不在 `memory_items` 的任何分区里（召回面看不到画像），也不落在别的租户的画像日志行里。

写入的 canary 收尾全部清掉，`relationship_state` 复原成 8.1 播种的那份原文（输出最后一行
的「复原=是」是按字符串相等比的，不是按「行存在」比的）。脚本可反复执行：开跑先清自己上一
次中止留下的行，中止后重跑不会把 canary 当成基线。
